export const ROGAN_GLADEN = String.raw`def rogan_gladen(observed: float, tpr: float, tnr: float) -> float:
    """The pass rate corrected for a judge's errors: (observed + TNR - 1) / (TPR + TNR - 1), kept between 0 and 1.
    A judge with TPR + TNR at or below 1 is no better than chance, and nothing can be corrected with it."""
    if tpr + tnr <= 1:
        raise ValueError(f"TPR + TNR is {tpr + tnr:.2f}: the judge is no better than chance")
    return min(1.0, max(0.0, (observed + tnr - 1) / (tpr + tnr - 1)))

def weighted_rates(labelled: list, pool: dict) -> tuple[float, float, list[float], list[float]]:
    """TPR and TNR with each labelled run standing for its stratum's share of the pool: its weight is how many runs
    the stratum holds over how many of its runs were labelled. Also returns the weights on each side."""
    drawn = Counter(stratum for stratum, _, _ in labelled)
    weight = {stratum: pool[stratum] / n for stratum, n in drawn.items()}
    passes = [(weight[s], verdict) for s, label, verdict in labelled if label == "pass"]
    fails = [(weight[s], verdict) for s, label, verdict in labelled if label == "fail"]
    tpr = sum(w for w, v in passes if v == "pass") / sum(w for w, _ in passes)
    tnr = sum(w for w, v in fails if v == "fail") / sum(w for w, _ in fails)
    return tpr, tnr, [w for w, _ in passes], [w for w, _ in fails]


def corrected_interval(observed: float, tpr: float, tnr: float, pass_weights: list[float], fail_weights: list[float],
                       repeats: int = 20000) -> tuple[float, float] | None:
    """A 95% interval for the corrected pass rate. Weighted labels carry less information than their number, so each
    side counts as its effective size, (sum of weights)² / sum of squared weights. TPR and TNR are drawn from Beta
    distributions holding that much evidence (with Jeffreys' half a label each way) and corrected; draws that leave a
    judge no better than chance are skipped. None if fewer than half the draws remain."""
    def effective(weights: list[float]) -> float:
        return sum(weights) ** 2 / sum(w * w for w in weights)

    n_pass, n_fail = effective(pass_weights), effective(fail_weights)
    rng, values = random.Random(0), []
    for _ in range(repeats):
        t = rng.betavariate(tpr * n_pass + 0.5, (1 - tpr) * n_pass + 0.5)
        f = rng.betavariate(tnr * n_fail + 0.5, (1 - tnr) * n_fail + 0.5)
        if t + f > 1:
            values.append(rogan_gladen(observed, t, f))
    if len(values) < repeats // 2:
        return None
    values.sort()
    return values[int(0.025 * len(values))], values[int(0.975 * len(values)) - 1]

<Subsection title="A judge's pass rate is biased" variant="a">

Every number a judge produces about a suite is a count of its own
verdicts, and its verdicts are wrong in known proportions. A judge with a
TNR of 67% passes a third of the runs that should fail; one with a TPR
below 100% fails some runs that should pass. The pass rate it reports is
pulled up by the first and down by the second.

If the error rates are known, the bias can be undone. The standard way,
from epidemiology, where it corrects disease prevalence for an imperfect
test, is the Rogan–Gladen estimator, and
[Husain and Shankar's `judgy` library](https://github.com/ai-evals-course/judgy)
uses it for exactly this:

> corrected pass rate = (observed pass rate + TNR − 1) / (TPR + TNR − 1)

Where it comes from is short. If the true pass rate is θ, the judge passes
TPR × θ of the runs that should pass and (1 − TNR) × (1 − θ) of the runs
that should fail, so the observed rate is TPR × θ + (1 − TNR) × (1 − θ).
Solving that for θ gives the formula. The denominator, TPR + TNR − 1, is
zero for a judge no better than a coin, which can't be corrected at all.

</Subsection>

Counted as they were drawn, the labels give a TPR of 0.92 and a TNR of
0.67, and the correction raises the rate to 84.3%. But they weren't drawn
as a random sample.
[The labelling set](/07-evaluation/07-measuring-judges/02-labels-from-people/)
took a fixed number from each stratum, by how the two judges had first
decided, so the strata where the judges split are heavily
over-represented: 4 of the 18 test labels come from a stratum holding 19
of the 430 runs in the pool, and 8 from one holding 311. Each label has to
stand for its stratum's share of the runs, so its weight is how many runs
the stratum holds over how many of them were labelled. That's the standard
weighting for any stratified sample. Weighted back to the runs, the judge
looks much better, with a TPR of 0.99 and a TNR of 0.88, and the
correction lowers the rate slightly, to 81.1%.

The interval is the real result. Weighted labels carry less information
than their count, because a few labels stand for most of the runs: the 12
labelled passes count as about 9.5 labels' worth, and the 6 labelled
failures as about 4. With that little evidence about the failures, the
corrected rate could be anywhere from about 63% to 100%. The point
estimate looks precise, and the interval says it isn't.

`judgy` reports the corrected rate with exactly this kind of interval,
and Husain's
[guide to building a judge](https://hamel.dev/blog/posts/llm-judge/)
warns that below about 60 labelled examples the intervals are often too
wide to support a useful conclusion. How many labels it takes is a
question the same resampling can answer, assuming the labels keep the same
mix:

judge question, drawn the same way, would pin the corrected rate within

number it wants to report: not "is the judge good?", but "how many labels
does this claim need?"

<Subsection title="When the correction can't be made" variant="a">

The correction needs both error rates, and each comes from labels on one
side:

- **TPR needs runs the person passed.** The planted-instruction judge's
  test set has none: every one of its labelled runs fails. Its TPR is
  unknown, so its pass rates can't be corrected, only reported with that
  gap stated.
- **TNR needs runs the person failed.** A judge whose labelled set held
  only passes could never show how often it misses a failure.

That's why the labelling set was chosen within each judge question by how
the judges had decided: it guarantees passes and fails on both sides
wherever they exist. Where the agent itself almost never passes, as with
the planted instruction, there's no way round it but labelling more runs.
It's also why the error rates have to be weighted: a set chosen to include
disagreements is the right set for finding a judge's errors, and the wrong
one for counting how often they happen, unless each label is weighted back.

</Subsection>
