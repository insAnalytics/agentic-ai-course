<Subsection title="Three records the conventions don't cover" variant="a">

OpenTelemetry's conventions describe model calls and tool calls. Three of
the records this course has kept fall outside them:

- **The context step's manifest.**
  [Module 4](/04-context-and-memory/12-assembling-the-context-step/03-seeing-inside-each-request/)
  recorded what went into each request, section by section, and said this
  module would build the tracing that the manifest is the context step's
  part of.
- **Module 6's check records.**
  [Module 6](/06-reliability/03-checks-in-the-loop/03-what-a-failed-check-does/)
  said to record which check fired, on what, and what happened next, and
  that this module would build those records into traces.
- **The version record.**
  [Module 6's `record_run`](/06-reliability/08-graceful-degradation/04-pinning-model-and-prompt-versions/)
  kept the model asked for, the model that answered, and a hash of the
  prompt and tool definitions.

A span can carry any attributes, so these go in as attributes of the
course's own. OpenTelemetry's naming guidance is to prefix names like these
with your company's reverse domain name, or with your application's name if
they're only used inside it, and never to borrow a namespace the
conventions already use, such as `gen_ai`, where a future version could
define the same name differently. This course uses `registry_agent.` as its
prefix.

All three are added the way
[Module 2's tracing hook](/02-the-agent-loop/11-from-hand-rolled-to-a-runtime/01-what-a-framework-actually-provides/#the-fix-by-hand-a-tracing-hook)
worked: by wrapping the pieces the loop calls, so the loop itself doesn't
change.

</Subsection>

  wrong later in a run, that's one of the first things to check.

<Subsection title="Checks as spans" variant="a">

A check record says where a check ran, on what, what it decided, and what
the loop did about it. As a span, that's one `check <point>` span per call,
with:

- `registry_agent.check.point`: which of Module 6's four points it ran at
- for checks on a tool call, the conventions' `gen_ai.tool.name` and
  `gen_ai.tool.call.id`
- `registry_agent.check.verdict`: `passed` or `blocked`
- for a block, the check's reason and the action Module 6's loop takes at
  that point

Two details matter. A check that blocks something hasn't failed, it's done
its job, so its span keeps status `UNSET` and the verdict attribute records
the block. And passes are recorded too, not only blocks. Module 6 counted
each check's catches and false blocks from its records, and a block rate
needs to know how often a check ran, not just how often it fired.
(OpenInference has a span kind for exactly this, `GUARDRAIL`;
OpenTelemetry's GenAI conventions don't have one yet.)

</Subsection>

<Subsection title="Instrumenting the registry agent" variant="b">

With the checks wrapped, the rest is two more wrappers and the version
record on the root span. `TracedChat` names each model call by the
conventions and adds the token counts and the answering model when the
client reports them; the course's scripted client doesn't, so this demo has
none. Tool spans get their call id from the `before_tool` check, which
always runs just before the tool. The root span carries Module 6's
configuration hash. The demo runs a scripted version of the refused change
from the pilot:

<LiveDemo client:load setupCode={INSTRUMENT_SETUP} code={INSTRUMENT_DEMO} />

*(The model's replies are scripted. `traced_checks` is the exercise's
reference version, already loaded for you.)*

Everything that happened is in one tree, in order: the model asked for
`set_model`, the tool failed, the `after_tool` check turned its result into
an error for the model, the model answered, and the answer passed its
check. The configuration hash on the root says which prompt and tool
definitions produced the run, so two runs can be compared knowing whether
their configuration matched.

This instrumentation is the one the module's main runs use, applied to the
registry agent's real client, tools and checks. Module 6's loop runs inside
it unchanged.

</Subsection>
