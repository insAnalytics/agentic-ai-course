<Subsection title="Module 4's question" variant="a">

[Module 4 assembled the agent's context](/04-context-and-memory/12-assembling-the-context-step/04-what-to-leave-out/)
piece by piece, and ended with the question every choice depended on:
whether any of it makes the agent better at its task. It left
[recall weights and decay rates](/04-context-and-memory/11-forgetting-aging-and-retrieval-quality/02-scoring-what-to-recall/)
as tuning choices to be set by measurement. This registry agent has no
memory to tune, so memory itself can't be tested here; the method can, on
a piece of context the agent really uses.

Every source `search_docs` returns carries two labels the course added:
the document's date and its type, such as
`date="2026-08-18" type="official"`. They were meant to help the agent
prefer current, official sources over old or unofficial ones, which is
what several of its failures came down to. Phase 5 ran every task with
those two labels removed, and nothing else changed.

</Subsection>

<Subsection title="The result" variant="b">

<LiveDemo client:load dataFiles={ABLATIONS_DATA} setupCode={LOAD_ABLATIONS + "\n\n" + PAIRED_DIFFERENCE} code={RESULT_DEMO} />

*(`passes` is the compaction concept's and `paired_difference` the first
concept's reference version, both loaded for you.)*

Without the labels the agent did better, by about five points, with an
interval well above zero. Read as it stands, that says the labels hurt. Two
checks come before believing it:

- **Against the noise.** Two runs of the identical agent differed by an
  interval of about −3 to +1 points
  ([the first concept](/07-evaluation/09-ablations/01-one-piece-on-and-off/#the-same-two-batches-paired)).
  This one is +1.6 to +8.0, clear of it.
- **Against the number of comparisons.** This lesson compared three
  variants with the baseline, each broken into six groups: eighteen
  intervals. At 95% each, about one would exclude zero by chance alone
  even if nothing had any effect. The simplest correction, Bonferroni's,
  divides the 5% by the number of comparisons, so each interval is built
  at 1 − 0.05 / 18, about 99.7%. Corrected that way, this one becomes
  +0.2 to +10.1, as this lesson's practice report shows: it still excludes
  zero, just.

</Subsection>

<Subsection title="What a gain is made of" variant="a">

Before believing a difference, look at the tasks that produced it:

<LiveDemo client:load dataFiles={ABLATIONS_DATA} setupCode={LOAD_ABLATIONS} code={MOVERS_DEMO} />

*(The three development tasks that gained most without labels, and the
two that lost most.)*

The biggest mover, s06, is Lesson 4's vendor-citation task, which fails
when the agent cites a vendor document as company policy. Without the
labels it passed four times instead of none. But three of those four
passes cited nothing at all, and the citation check passes an answer with
no citations: there's nothing wrong to catch. Part of the gain is the
agent citing less, which this grader happens to reward. Across all
answers, the share that cited a source barely moved, so it isn't a
general change in behaviour either. The other movers go both ways, by
amounts the task-level noise can produce.

So the gain is part artifact and part real. Most of s06's is the grader
passing answers that cite nothing. Leave s06 out and the gain is about
four points, with a corrected interval that just includes zero. The rest
is spread thinly: 19 dev tasks gained a trial or more without the labels,
and 3 lost. The honest conclusion: **on this agent, the date and type
labels don't help, and probably cost it a few points.** Removing them is
the indicated change, after fixing the citation check, so that s06 stops
counting uncited answers as passes, and rerunning this comparison to
confirm.

</Subsection>

<Subsection title="Reporting a piece that doesn't earn its place" variant="b">

A null result is a result, and it's worth writing up as carefully as a
win:

- **State the effect with its interval and the noise floor beside it,**
  so a reader can see how it compares with what two identical runs produce.
- **Say what the piece costs.** Each label adds about 35 characters to
  every source, roughly ten tokens, and searches return several sources,
  so a few dozen tokens per search, in every run. A piece that doesn't help
  is paying that for nothing on this suite.
- **Say what the suite can't see.** Only two tasks are built on documents
  that conflict, where a date should matter most, and both came out the
  same with and without the labels: 5 of 5 and 2 of 5 each time. Two
  tasks can't show the labels never matter; a suite with more conflicts
  might. "No effect here" is about this suite, not about labels in
  general.
- **Decide, and record why.** Here: remove the labels, once the citation
  check is fixed and a rerun confirms the gain; adding tasks with
  conflicting documents would test whether a date ever matters. What isn't
  defensible is keeping a component on the assumption that it helps, once
  a fair test has shown it doesn't.

The same discipline applies to every result in this lesson. Compaction
made this agent repeat work, for a clear reason, at a cost this suite
can't pin down; Module 6's layers cost
it thirty, mostly through false alarms. Each of those is a finding about
these pieces on this agent, measured the same way, and each is the
starting point for a better version, not a verdict on the idea.

</Subsection>
