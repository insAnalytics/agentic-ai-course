<Subsection title="The changes" variant="a">

Phase 6 made three changes to the registry agent, each the kind this
lesson started from, and ran the full suite on each with the same 5
trials per task as the baseline:

- **A serving change.** The agent's server quantized the same pinned
  model, same repository and revision, to FP8 as it loaded. The model ID
  it reports didn't change.
- **A prompt change.** Two lines added to the system prompt, aimed at two
  failures earlier lessons found: telling the agent which document types
  state company policy, since it kept citing vendor documents as rules;
  and telling it to read a record back after changing it, since it kept
  reporting lost writes as done.
- **A fix to Module 6's layers.** Version 2 of three layers, aimed at the
  false alarms Lesson 9 read:
  - the intent check accepts names the agent found by lookup
  - grounding ignores list numbers and identifiers
  - the support judge is given one claim per sentence

Each was gated against the baseline, the last known-good run, as
[the gate concept](/07-evaluation/10-regression-tests/02-a-gate-that-doesnt-flake/)
built it:

*(`settings`, `passes` and `results` are this lesson's and Lesson 9's
setups; `what_changed`, `paired_difference` and `gate` are the reference
versions from the first concept, Lesson 9 and the gate concept, all loaded

task-file version, which changed for every run since the baseline, is

FP8 changed one setting the config hash can't see, and the gate found no
regression: the same pinned model, served quantized, did as well on this
suite. The prompt change passed with a small gain. The layer fix failed.

</Subsection>

<Subsection title="Reading a pass: the prompt change" variant="b">

A gate that passes says nothing got worse. It doesn't say the change did
what it was for. That needs the tasks it was aimed at:

<LiveDemo client:load dataFiles={DATA} setupCode={SETUP} code={TARGETS_DEMO} />

The read-back line worked: the lost-write tasks went from never passing
to passing four or five times in five. In a run read from s01, the agent
tried the change twice, read the record back after each attempt, and
told the user the registry still showed the old model. It didn't fix
a14, where the agent emails the team that the change is done before it
has checked: the new line covers what the agent tells the user, not the
order of its actions.

The document-type line did nothing measurable. The vendor-citation tasks
stayed where they were. Knowing which types are policy wasn't enough to
stop the agent citing a vendor page for a rule, and a next attempt would
need a different fix, measured the same way.

</Subsection>

<Subsection title="Reading a failure: the layer fix" variant="a">

<LiveDemo client:load dataFiles={DATA} setupCode={SETUP} code={LAYERS_DEMO} />

Two of the three fixes worked. The intent check, which objected in 44
runs, objected in none, and grounding's objections fell from 132 runs to
24. Fewer answers were withheld, 228 instead of 376.

The third fix brought bugs of its own, written in the course's content
chat (the Claude model this course is drafted with, not a person) and
caught by this run:

- **It mangled agent names.** To give the judge clean sentences, version
  2 strips markdown, and that includes underscores, so `research_agent`
  reached the judge as `researchagent`. The judge correctly said no
  source supports a claim about an agent that doesn't exist. That
  withheld 47 answers.
- **It sent empty claims.** A list line that's only a citation became a
  "sentence", and removing the citation left nothing. The judge was asked
  about nothing 13 times and called it unsupported often enough to
  withhold 9 answers.

The rest of what it withheld were mostly attribution sentences, such as
"These are defined in the Monitoring guide", which no source supports
because they're about the answer rather than the system, plus a few real
catches, such as a citation to a section no tool returned.

This is the case for running the whole suite on a fix. The unit tests
for version 2 passed: every scripted case was right, including one that
checked the judge received exactly one claim. The scripted claim
contained no underscore and no bare citation line, so the bugs went
through. A version 3 would keep identifiers intact, skip empty claims,
and leave attribution sentences to the citation check, and it would go
through this same gate.

</Subsection>
