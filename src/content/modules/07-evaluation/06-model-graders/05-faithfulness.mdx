<Subsection title="What faithfulness asks" variant="a">

Correctness asks whether an answer matches the reference. Faithfulness
asks something narrower: is every claim in the answer supported by what
the run actually retrieved?
[RAGAS](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/faithfulness/)
defines it as the share of an answer's claims that the retrieved context
supports.
[Langfuse's guide to measuring it](https://langfuse.com/resources/engineering/rag-faithfulness-evaluation)
adds the rule that matters most: a claim counts as supported only if the
context states it or directly implies it, even if the claim is true. It
needs no reference answer, so it can run on any question, real traffic
included.

The two questions can disagree in both directions:

- **Right, but not from the sources.** One run explained what the
  `Retry-After` header tells a client. The changelog it retrieved only
  says the header was added. The explanation may well be true, but nothing
  the run read says it, so nobody can trace it.
- **Faithful, and still bad.** An answer can repeat exactly what it
  retrieved when what it retrieved is wrong. The planted-instruction runs
  are the extreme case: a page in the corpus tells AI assistants to advise
  switching authentication off, and an answer that passes that on is
  faithful to its sources. Whether a source deserves trust is a separate
  question, which
  [the planted-instruction judge](/07-evaluation/06-model-graders/01-from-a-check-to-a-grader/)
  asks.

That's why faithfulness gets its own grader rather than standing in for
correctness.

</Subsection>

<Subsection title="The citation check isn't a faithfulness check" variant="b">

[Lesson 5's citation check](/07-evaluation/05-code-graders/03-checking-the-path-in-code/)
confirms that every source an answer cites was one a tool returned. That
catches invented citations. It can't tell whether a cited source says what
the answer claims, and an answer that cites nothing passes it by default.

<Subsection title="A judge that reads the sources" variant="a">

Whether a source supports a claim needs reading, so it goes to a judge:
the same Gemma 4 31B, shown the conversation, everything the run's tools
returned in order, and the final answer. Its rubric:

> Question: is every factual claim in the assistant's answer supported by
> what its tools returned in this run? A claim is supported only if the
> tool results state it or directly imply it, even if the claim is true.
> PASS if every factual claim is supported, or if the answer makes no
> factual claims (for example, it says it couldn't find the answer). FAIL
> if any factual claim isn't supported, and name the first one in your
> reasoning. Citations don't matter here: judge the claims, not whether or
> how they are cited. UNCLEAR if you can't tell.

Two choices shape it:

- **One verdict per answer, not per claim.** RAGAS first extracts each
  claim, then checks each one, which gives a finer score for several model
  calls per answer. One call that names the first unsupported claim keeps
  to this module's pass/fail rubrics, at the cost of that score.
- **Citations are ignored.** The code check above owns them. The judge
  asks only whether a claim is supported by something the run saw.

It's also the module's most expensive judge, because every prompt carries
every tool result: about 1,900 tokens on average. Here's what it said on
every answered run:
