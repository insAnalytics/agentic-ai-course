def serialize(x) -> str:
    # byte-for-byte form, as a cache sees it: key order matters, exactly as sent
    return json.dumps(_plain(x))

def first_divergence(previous: dict, current: dict) -> dict:
    """Where does current stop matching previous, and how much of it could be read from the cache?"""
    reusable = 0
    if serialize(current["tools"]) != serialize(previous["tools"]):
        return {"diverges_at": "tools", "reusable_tokens": 0}
    reusable += count_tokens(current["tools"])
    if serialize(current["system"]) != serialize(previous["system"]):
        return {"diverges_at": "system", "reusable_tokens": reusable}
    reusable += count_tokens(current["system"])
    for i, old in enumerate(previous["messages"]):
        if i >= len(current["messages"]) or serialize(current["messages"][i]) != serialize(old):
            return {"diverges_at": f"messages[{i}]", "reusable_tokens": reusable}
        reusable += count_tokens(old)
    return {"diverges_at": None, "reusable_tokens": reusable}

def cost_of_run(requests: list, read_multiplier: float, write_multiplier: float) -> int:
    """Cost of the requests actually sent, using first_divergence to see what each could reuse."""
    total = 0.0
    previous = None
    for request in requests:
        size = count_tokens(request["tools"]) + count_tokens(request["system"]) + count_tokens(request["messages"])
        reused = first_divergence(previous, request)["reusable_tokens"] if previous else 0
        total += reused * read_multiplier + (size - reused) * write_multiplier
        previous = request
    return round(total)
`;

export const WORKSPACE_FUNCS = String.raw`
class Workspace:
    """Files the agent explores by path: list them, search them, read a slice. Never everything at once."""
    def __init__(self, files: dict, max_matches: int = 20, max_lines: int = 40):
        self.files = files
        self.max_matches = max_matches
        self.max_lines = max_lines

    def list_files(self, prefix: str = "") -> str:
        paths = [path for path in sorted(self.files) if path.startswith(prefix)]
        if not paths:
            return f"No files under {prefix!r}."
        return "\n".join(f"{path} ({len(self.files[path].splitlines())} lines)" for path in paths)

    def grep(self, pattern: str, prefix: str = "") -> str:
        """Lines containing pattern, ignoring case, as PATH:LINE: TEXT. At most max_matches, then a count of the rest."""
        hits = []
        for path in sorted(self.files):
            if path.startswith(prefix):
                for number, line in enumerate(self.files[path].splitlines(), start=1):
                    if pattern.lower() in line.lower():
                        hits.append(f"{path}:{number}: {line[:200]}")
        if not hits:
            return f"No lines match {pattern!r} under {prefix!r}."
        shown = hits[:self.max_matches]
        if len(hits) > len(shown):
            shown.append(f"... and {len(hits) - len(shown)} more. Narrow the pattern or the path.")
        return "\n".join(shown)

    def read_file(self, path: str, start: int = 1) -> str:
        """Up to max_lines lines of one file, from line start, with a header saying where the rest is."""
        if path not in self.files:
            return f"Error: no file {path}. Use list_files to see what exists."
        lines = self.files[path].splitlines()
        if not 1 <= start <= len(lines):
            return f"Error: {path} has lines 1 to {len(lines)}."
        chunk = lines[start - 1:start - 1 + self.max_lines]
        end = start + len(chunk) - 1
        header = f"{path}, lines {start}-{end} of {len(lines)}"
        if end < len(lines):
            header += f"; read_file(path, start={end + 1}) for more"
        return header + "\n" + "\n".join(line[:200] for line in chunk)

def require_reading(name: str, required: dict, read: set):
    """None if the call may run; otherwise an error saying which guide must be read first."""
    guide = required.get(name)
    if guide is not None and guide not in read:
        return f"Error: read the {guide} guide first, with read_guide(\"{guide}\"), then call {name} again."
    return None
`;

<Subsection title="The same idea, applied to data" variant="a">

The previous concepts loaded tools and guides only when they were needed.
The same question comes up for the data a task works on: logs, configs,
documents, records. The simple answer is to gather what might be relevant
and put it in the context before the agent starts. Anthropic's
[guide to context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
describes the alternative many agents have moved to. The agent keeps
**lightweight references**, such as file paths, queries and links, and
uses tools to load what it needs *while it works*. Coding agents are the
familiar example: rather than being handed a whole repository, they list
directories, search with `grep`, and read the few files that matter. The
Manus team describes the file system the same way, as context that's
unlimited in size and that the agent reads and writes on demand.

It's the idea behind
[Lesson 6's handles](/04-context-and-memory/06-offloading-context-to-storage/01-keep-the-reference-not-the-result/)
too. A handle, a path or a query costs a few tokens, and the data behind it
stays outside the window until it's asked for.

</Subsection>

<Subsection title="A workspace to explore" variant="b">

Three tools cover most exploring, and each one has a limit on how much it
can return, so that no single call can flood the context:

- **`list_files`** shows what exists, with each file's size, so the agent
  can see what it's dealing with before it reads anything.
- **`grep`** finds the lines that contain a pattern, each with where it is.
  A pattern that matches too much returns the first few matches and a count
  of the rest, which tells the agent to narrow its search.
- **`read_file`** reads a slice of a file, and says where the rest is.

Paths are looked up in the workspace and nowhere else, which is the rule
from
[the guide library](/04-context-and-memory/07-just-in-time-context-and-dynamic-tool-exposure/03-instructions-and-reference-material-on-demand/#whose-instructions-are-these)
again. You'll write `grep` and `read_file` in the exercise below.

</Subsection>

Everything up front is one large request of about 23,000 tokens, nearly all

billing_agent's lookup has taken 4.8 seconds since its 10:00 release. That's

which run to millions of lines, pasting everything in isn't possible at all.

The wrong first guess shows the price of exploring. Searching for
"exception" found nothing, and the agent had to look around before
searching again. That's two extra round trips, each adding a little to
every request after it. Exploring trades tokens for time: every step is
another model call, and an agent can wander into dead ends. The last lines
of the output show why every tool is bounded: a search for "INFO" matches
almost every line, and returns twenty and a count.

</Subsection>

<Subsection title="A map, then explore" variant="b">

The exploring runs didn't start blind. Their system prompt said what the
workspace holds, in one line: logs in one folder, configs in another. That
**hybrid** is how most agents that explore are set up. A little is loaded
up front: what exists, how it's laid out, and the conventions that always
apply. Everything else is found when needed. Claude Code works this way:
a project's `CLAUDE.md` file is loaded at the start of every session, and
the code itself is explored with search and read tools.

It's the same shape as the guide index and the tool catalog in this
lesson's earlier concepts. A short, fixed description sits in the prefix,
and it's good enough to know where to look. The details arrive as tool
results, at the end of the conversation.

</Subsection>

<Subsection title="What exploring can miss" variant="a">

Loading on demand has a failure that loading everything doesn't: **the
agent has to know to look.** A model that never thinks to read the rollback
runbook improvises a rollback. A model that searches for the wrong word
decides there's nothing to find. Nothing in the context tells it that what
it needed was one call away.

Three defenses, from cheapest to strongest:

- **What must always apply stays in the prefix.** A rule like "never roll
  back during business hours without approval" can't depend on the agent
  choosing to read it. Short rules that apply to every task are loaded up
  front, as standing instructions are.
- **Say when to read, not just what's there.** An index line like
  "rollback: undo a bad release. Read before any rollback" tells the model
  when it applies, not only what it covers.
- **Make the dispatcher require it.** For the actions that matter most,
  code can refuse to run a tool until its guide has been read. It's
  [the first concept's gating](/04-context-and-memory/07-just-in-time-context-and-dynamic-tool-exposure/01-what-you-load-and-where-it-goes/#stages-without-changing-the-list),
  keyed on what the agent has read rather than on the stage:

The refusal says exactly what to do, so the agent recovers in one step, and
the rule holds whatever the model decides. How often an agent loads what it
should on real tasks is something to measure, not assume, which is Module

</Subsection>
