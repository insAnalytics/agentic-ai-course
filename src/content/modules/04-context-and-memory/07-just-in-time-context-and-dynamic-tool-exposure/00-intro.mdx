<WhyItMatters>
  An agent connected to a few real services can easily carry tens of
  thousands of tokens of tool definitions and runbooks on every request,
  almost all of them unused at any given step.
  [Lesson 1](/04-context-and-memory/01-the-context-budget/01-what-fills-the-window/)
  measured it: on the first turn, tool definitions were most of the
  request. Loading only what's needed is the obvious fix, and done
  carelessly it's expensive. The tool list and system prompt are the start
  of every request, so changing them costs the cache everything after
  them, and removing a tool the history mentions confuses the model.

  This lesson loads tools, instructions, reference material and the data a
  task works on only when they're needed, while keeping the start of every
  request exactly the same, from the first turn to the last.
</WhyItMatters>
