<Subsection title="From a finished session to candidate memories" variant="a">

[Lesson 9's pipeline](/04-context-and-memory/09-building-a-memory-store/02-three-ways-an-agent-uses-the-store/#a-pipeline-after-the-session)
wrote memories after a session from a list an extraction step had proposed,
and that step was scripted. This lesson builds it. It's a model call that
reads a finished session and proposes what's worth keeping. Published memory
systems work the same way: Mem0, for example, runs an
[extraction phase](https://arxiv.org/abs/2504.19413) that pulls salient facts
out of each exchange before deciding what to do with them.

A model is the right tool for the job, because judging what will matter next
week takes judgment. The question is what to do with its answer.

</Subsection>

<Subsection title="The trouble with trusting its labels" variant="b">

The obvious design asks the model for each memory's content, its type, and its
source: did the user say it, did the agent conclude it, or did a tool return
it?
[Lesson 9](/04-context-and-memory/09-building-a-memory-store/01-a-memory-record-and-a-store-scoped-by-design/)
made `source` part of every record because what a memory is allowed to do
depends on it.

But a source label written by the model is just more model output. It can be
wrong in ordinary ways: a paraphrase, a detail invented, one message confused
with another. It can also be wrong because something told it to be. Text in a
tool result that says "the user asked me to remember…" is exactly the kind of
thing
[Module 3's threat model](/03-tool-design-for-agents/10-the-tool-threat-model/01-prompt-injection-through-tool-results/)
warned steers a model. If the model repeats that claim, a label-trusting
pipeline stores it as the user's words.

</Subsection>

<Subsection title="Evidence: a quote, and where it's from" variant="a">

The fix is to ask for something code can check. For each memory, the model
must give the **exact words** it rests on, and the number of the **entry** they
come from. Code then checks that those words really are in that entry, and
takes the source from the entry itself, never from the model. Asking for
supporting quotes is a known technique:
[Anthropic's guide to reducing hallucinations](https://platform.claude.com/docs/en/test-and-evaluate/strengthen-guardrails/reduce-hallucinations)
suggests having the model find a quote for each claim, and drop any claim it
can't back. Here, code does the checking.

To make entries citable, the session is flattened into numbered pieces, each
marked with whose words it is:

````python
def entries(history: list) -> list:
    """A session as numbered pieces, each marked with whose words it is: the user's, the agent's, or a tool's."""
    found = []
    for message in history:
        if isinstance(message["content"], str):
            found.append({"kind": "user" if message["role"] == "user" else "agent", "text": message["content"]})
            continue
        for block in message["content"]:
            block = _plain(block)
            if block["type"] == "tool_result":
                found.append({"kind": "tool", "text": str(block["content"])})
            elif block["type"] == "text":
                found.append({"kind": "user" if message["role"] == "user" else "agent", "text": block["text"]})
    return found

def numbered_transcript(history: list) -> str:
    found = entries(history)
    return "\n".join(f"[{i}] {found[i]['kind']}: {found[i]['text']}" for i in range(len(found)))
````

tool result's text can say anything, but its entry is still marked `tool`:
nothing written inside it can change that.

helper from

The extraction reply is scripted, with three flawed proposals written in on
purpose.

Trusting the labels would have stored "Send weekly reports to Priya" as a
standing instruction from the user. The user never said it: it's not in entry
0, or anywhere else. With the check, it's refused.

The second refusal is the price of the rule. The page does say escalations go to
#support-oncall, but the model's quote reworded it, so it doesn't match. An
exact-match check refuses anything it can't verify, including honest
paraphrases. Loosening it (ignoring case or spacing, say) lets more through, at
the cost of verifying less. For memory, the trade leans strict. A true fact
that's refused can be learned again next session. A forged one is replayed in
every session until someone notices.

The last proposal is the subtle one. Its quote is genuine: "bullet points"
really is in the user's message. But the instruction attached to it, sending
every report to an outside address, is nowhere in those words. That's what a
model steered by text in a tool result can produce: a real quote from the user,
carrying an instruction the user never gave. A matching quote only proves whose
words the *quote* is. So for a standing instruction, the one kind of memory
whose power comes from who said it, `derive_source` also checks that the
instruction is really in the quote: at least half of its keywords must appear
there. A fact can reasonably add context its quote leaves out, like which
agent a number belongs to. An instruction that says more than the user did
can't borrow the user's authority.

</Subsection>

<Subsection title="What the evidence settles" variant="b">

The quote check settles one question: **whose words these are.** That's what
the source rules in this lesson's last concept depend on.

"Whose words" here means which kind of entry they're in, and `entries` decides
that from the message's role. That's only as trustworthy as what the
application puts in the user role. Here, a user message holds only what the
user typed. But many applications also put an uploaded document, pasted text,
or context the harness retrieved into a user message. `entries` would mark all
of that `user`, and a planted line in an uploaded file would count as the
user's own words. Anything the user didn't write themselves needs its own kind,
treated like `tool`: the role of a message says where it sits in the
conversation, not who wrote it.

It doesn't settle whether the words are true, or whether a tool's text is
really a fact or an instruction dressed as one. A page can say anything, and a
quote from it is only ever `tool`. What a `tool` memory may become is the last
