<Subsection title="Closing synthesis — one operational decision, every piece" variant="a">

This isn't graded — it's a chance to pull quantization, model selection,
and rate-limit handling into one deployment decision.

You're deploying an agent backend under real cost and reliability
constraints: moderate request volume, mixed task difficulty (mostly
simple lookups, occasional genuinely complex planning), and a strict
monthly budget. Before checking below, reason through: self-host or use
an API? If self-hosting, what quantization level? What model
size/reasoning tier for the two different task types? How do you handle
being rate-limited in production?

*Reasoning to check against:* given a strict budget and *moderate*
volume (not massive scale), an **API** is likely the more practical
starting choice —
[self-hosting's real ops burden](/01-llm-foundations/11-quantization-cost-and-operational-concerns/02-the-model-landscape-and-selection/#open-weight-vs-closed-models)
isn't obviously worth taking on yet, though it stays a real option if
volume grows enough to justify it. For the mixed task difficulty,
[the model-landscape concept's size-tier and reasoning-axis principles](/01-llm-foundations/11-quantization-cost-and-operational-concerns/02-the-model-landscape-and-selection/#size-tiers-within-one-provider-s-lineup)
both apply independently: route simple lookups to a small, standard
model; route genuinely complex planning to a larger and/or
reasoning-capable model — never the reverse, and never one tier for
everything regardless of task. If self-hosting *were* chosen instead,
[the quantization concept's tradeoff](/01-llm-foundations/11-quantization-cost-and-operational-concerns/01-quantization/#the-real-tradeoff)
becomes directly relevant: INT8 as a reasonable default balancing cost
and quality, reserving INT4 only if the budget genuinely demands it and
some quality loss is acceptable. And regardless of which model or
provider is chosen,
[the rate-limits concept's exponential backoff](/01-llm-foundations/11-quantization-cost-and-operational-concerns/04-provider-side-rate-limits/#the-real-handling-pattern-exponential-backoff-not-just-send-less)
is a necessary piece of any production system calling an external API —
not optional infrastructure, since a `429` under real load is a *when*,
not an *if*.

This is the actual shape of the judgment this entire module has been
building toward: not memorized facts, but a coherent set of reasoned
tradeoffs, ready to apply the moment a real system actually needs
building.

</Subsection>
