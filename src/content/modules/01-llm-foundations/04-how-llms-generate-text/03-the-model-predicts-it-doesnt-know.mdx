<Subsection title={'There is no separate "fact-checking" step anywhere in this process'} variant="a">

Look back at exactly what's happened across
[the logits-and-probability concept](/01-llm-foundations/04-how-llms-generate-text/01-logits-and-the-probability-distribution/)
and
[the autoregressive-generation concept](/01-llm-foundations/04-how-llms-generate-text/02-autoregressive-generation/):
a learned scoring function produces a logit for every possible token,
softmax turns those into a probability distribution, one token gets
picked, and the whole process repeats. Nowhere in that loop is there a
step that consults a database of facts, checks whether a candidate
token is *true*, or does anything different depending on whether the
"right" answer is well-established or completely unknown. It's the
exact same mechanism, every single time, regardless of what's actually
being asked.

Whatever an LLM "knows" isn't stored anywhere as retrievable facts —
it's encoded implicitly in the model's learned parameters (the token
embeddings,
[the attention weights](/01-llm-foundations/03-attention-and-transformer-architecture/02-the-attention-mechanism/),
everything adjusted during training), expressed only through this same
logit-computation process. There's no separate "knowledge module" being
queried — just one statistical scoring function, applied identically to
every possible continuation.

</Subsection>

<Subsection title="The same mechanism, whether the answer is grounded or not" variant="b">

<LiveDemo client:load code={`import math

def softmax(logits: dict) -> dict:
    exp_values = {token: math.exp(score) for token, score in logits.items()}
    total = sum(exp_values.values())
    return {token: value / total for token, value in exp_values.items()}

# "The capital of France is" -- an extremely well-established fact
fact_logits = {"Paris": 8.9, "Lyon": 1.2, "Marseille": 0.8}

# "The founder of the fictional city of Meridian Falls was" -- no real answer exists at all
fabricated_logits = {"Aldric Thorne": 6.1, "Marcus Reed": 5.9, "Elena Vasquez": 5.3}

print(softmax(fact_logits))
print(softmax(fabricated_logits))`} />

This is
[the exact same `softmax` function from the logits-and-probability concept](/01-llm-foundations/04-how-llms-generate-text/01-logits-and-the-probability-distribution/),
applied without any modification to both cases. For the genuine fact,
one token dominates almost totally — `"Paris"` at roughly `99.9%` —
reflecting how overwhelmingly consistently that answer appears across
training data. For the fabricated scenario, where no real answer exists
anywhere in the model's training data at all, the process still runs
identically and still produces a full, seemingly confident distribution
— `"Aldric Thorne"` comes out ahead at roughly `44%`, a genuinely
plausible-sounding name, despite referring to something entirely
invented — but notably *without* the same overwhelming dominance the
genuine fact got, since no single fabricated name is reinforced by real
training data the way `"Paris"` is. There's no explicit truth check
anywhere in the computation. The shape of the distribution is the only
trace of the difference, and it's an unreliable signal:
[as the hallucination concept shows](/01-llm-foundations/04-how-llms-generate-text/04-hallucination-as-a-direct-consequence/#plausible-isn-t-the-same-as-rare-sometimes-it-s-a-popular-misconception),
a model can be confident *and* wrong. Both outputs come from precisely
the same mechanism, with no internal flag marking one as more
trustworthy than the other.

</Subsection>

<Subsection title={'Why "predicts, doesn\'t know" is the accurate way to describe this'} variant="a">

This is the actual, mechanical reason it's more accurate to say a model
*predicts* a continuation than to say it *knows* an answer: prediction
is genuinely all that's happening, every time, for every token — a
statistical best-guess given everything that came before, produced by
one uniform process that has no separate faculty for distinguishing
recalled truth from confident fabrication. This is exactly what makes
hallucination possible — not a malfunction in this process, but this
exact process working precisely as it's built to.

</Subsection>
