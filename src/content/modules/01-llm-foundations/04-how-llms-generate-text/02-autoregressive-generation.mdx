<Subsection title="The model never generates more than one token at once" variant="a">

[the previous concept showed how a single next-token probability distribution gets produced](/01-llm-foundations/04-how-llms-generate-text/01-logits-and-the-probability-distribution/).
A full response — a sentence, a paragraph — is never generated in one
step. The model picks one token from that distribution (exactly *how*
it picks — always the top one, or something more varied — is a later
lesson's job), appends that single token onto the sequence, and then
runs the process again: conceptually, a pass through every transformer
layer over the whole sequence, including the token it just generated —
to produce the distribution for the *next* token.

<LiveDemo client:load code={`def predict_next_token(sequence: list) -> str:
    # a toy stand-in for a real model's full forward pass + softmax + selection --
    # a real model runs a pass through every layer to produce each new token
    toy_rules = {
        ("The", "cat", "sat"): "on",
        ("The", "cat", "sat", "on"): "the",
        ("The", "cat", "sat", "on", "the"): "mat",
    }
    return toy_rules.get(tuple(sequence), ".")

sequence = ["The", "cat", "sat"]
for _ in range(3):
    next_token = predict_next_token(sequence)
    sequence.append(next_token)
    print(sequence)`} />

Each call to `predict_next_token` receives the *updated* sequence,
including everything generated in every previous call — `"on"` from the
first call is already part of the sequence by the time the second call
runs. This is the actual meaning of "autoregressive": the model
predicts its next output by looking at *its own prior output*, fed back
in as input, over and over, one token at a time.

</Subsection>

<Subsection title="Why this matters computationally" variant="b">

Every single one of those calls is
[the entire logit/softmax computation from the previous concept](/01-llm-foundations/04-how-llms-generate-text/01-logits-and-the-probability-distribution/),
producing exactly one new token. Conceptually, each call looks at the
whole sequence so far.
[The KV cache, later in this module](/01-llm-foundations/06-context-windows-and-kv-cache/03-kv-cache/),
shows how real systems avoid recomputing the work for earlier tokens,
but each new token still costs one pass through every layer. A ten-token
response requires ten passes through the model; a thousand-token response
requires a thousand. Generation cost
scales directly with how many tokens actually get produced — a fact
that becomes directly relevant once this module reaches test-time
compute and reasoning models: a model that "thinks" by generating more
tokens before its final answer is spending real, additional passes
through this exact loop, not some separate, cheaper reasoning process.

</Subsection>
