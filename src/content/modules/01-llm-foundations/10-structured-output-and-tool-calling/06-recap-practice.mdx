<Subsection title="Closing synthesis — design a new tool, end to end" variant="a">

This isn't graded — it's a chance to apply every concept in this lesson
to a scenario not already covered.

Design a `search_flights` tool taking `origin`, `destination`, and
`date` as arguments. Before checking below, work through: what would
its Pydantic schema look like? When is the model's `arguments` output
for this tool *guaranteed* to match that schema, and by what mechanism? What
does your own code's responsibility look like once the model requests
this tool? What does the second API call in the round trip actually
contain?

*Reasoning to check against:* the schema is
[an ordinary Pydantic `BaseModel`](/01-llm-foundations/10-structured-output-and-tool-calling/03-from-a-pydantic-model-to-a-schema/#generating-the-schema-directly-from-a-model-you-already-know)
— `origin: str`, `destination: str`, `date: str` — converted via
`.model_json_schema()`. The guarantee comes from
[constrained decoding masking any token that would produce an invalid shape](/01-llm-foundations/10-structured-output-and-tool-calling/02-constrained-decoding/#masking-invalid-tokens-before-softmax-ever-runs),
not from the model choosing to comply, and it only applies when the
provider's strict mode is on: with strict mode on, constrained decoding guarantees the arguments match the schema; without it, they're usually but not always well-formed. Your code's responsibility,
[per the separation between the model's request and your code's decision to run it](/01-llm-foundations/10-structured-output-and-tool-calling/04-tool-calling/#why-this-separation-matters),
is deciding whether to actually run a real flight search with those
parsed arguments — nothing forces execution just because the model
requested it; validating the date format or rejecting an implausible
request before calling a real, possibly costly search API is entirely
your call. The second API call's `messages` array contains
[the original question, the assistant's tool-call request, and a new message holding the search results](/01-llm-foundations/10-structured-output-and-tool-calling/05-the-full-round-trip/#building-the-growing-conversation-step-by-step)
— the exact same three-message growth pattern already demonstrated,
just with different content.

The pattern worth taking away from this entire lesson: every piece of
"agentic" behavior this course will build toward — deciding to act,
executing something real, incorporating the result — is built from
mechanisms already fully understood by this point, composed together,
not something categorically new.

</Subsection>
