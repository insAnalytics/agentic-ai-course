<WhyItMatters>
  An agent that only ever answers one request at a time, with one response at
  the end, is a narrow slice of what real agent systems actually need to do:
  stream a response as it's generated, let a user cancel a running task, push
  a status update to everyone watching, or call an internal tool service
  reliably at scale. Every protocol in this lesson is a different, deliberate
  answer to "how should these two things actually talk to each other" — and
  choosing correctly, not defaulting to whichever one you know best, is as
  much the point as knowing how to implement any one of them.
</WhyItMatters>
