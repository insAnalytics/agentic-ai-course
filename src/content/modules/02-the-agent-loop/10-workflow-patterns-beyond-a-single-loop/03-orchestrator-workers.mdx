<Subsection title="Decompose, dispatch to many, aggregate" variant="a">

Genuinely distinct from both prior patterns: routing picks *one* fixed
path; orchestrator-workers decomposes a task into several sub-tasks,
dispatches *all* of them to workers, and aggregates the results into
one output — and that decomposition is itself a real, scripted call:
[the same `PlanBlock` shape from Lesson 8's goal decomposition](/02-the-agent-loop/08-planning-and-decomposition/01-goal-decomposition/#decomposing-before-executing-anything),
not a list hardcoded into the orchestrator's own code.

<LiveDemo client:load setupCode={FAKE_CLIENT} code={`import asyncio

class PlanBlock:
    def __init__(self, sub_tasks: list):
        self.type = "plan"
        self.sub_tasks = sub_tasks

async def worker(sub_task: str) -> str:
    await asyncio.sleep(0.3)
    return f"completed: {sub_task}"

async def run_orchestrator(client, goal: str) -> str:
    response = client.create(messages=[{"role": "user", "content": f"Decompose this goal into sub-tasks: {goal}"}])
    sub_tasks = response.content[0].sub_tasks

    worker_results = await asyncio.gather(*(worker(task) for task in sub_tasks))
    return "\\n".join(worker_results)

client = FakeLLMClient(scripted_responses=[
    PlanBlock(sub_tasks=["Create research_agent", "Create support_agent", "Create billing_agent"]),
])

summary = asyncio.run(run_orchestrator(client, "Set up a full team of agents"))
print(summary)`} />

(The fake client's classes are already defined for this demo.) The
orchestrating call happens exactly once, upfront, before any worker
runs — `sub_tasks` is whatever the model actually decided the goal
decomposes into, not a fixed list the orchestrator's own code already
knew. Each worker has a fixed job — run its one sub-task, report back —
never deciding what to do next dynamically the way
[a full agent loop from Lesson 4 onward](/02-the-agent-loop/04-writing-the-loop-by-hand/00-intro/)
would. This is genuinely different from a full agent loop, not a
smaller version of one: once the plan comes back, the sub-tasks are
fixed for the rest of the run,
[this lesson's parallel dispatch](/02-the-agent-loop/10-workflow-patterns-beyond-a-single-loop/02-parallelization/)
runs them together, and aggregation is a final, fixed join step — no
open-ended decision-making anywhere in the structure.

</Subsection>
