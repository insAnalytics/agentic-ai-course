<Subsection title="The same agent, in LangChain" variant="a">

```python
from langchain.agents import create_tool_calling_agent, AgentExecutor
from langchain.tools import tool
from langchain_anthropic import ChatAnthropic
from langchain_core.prompts import ChatPromptTemplate

@tool
def check_agent_exists(name: str) -> bool:
    """Check whether an agent with this name already exists in the registry."""
    return name in registry

@tool
def create_agent_entry(name: str, model: str) -> str:
    """Create a new agent entry in the registry."""
    registry[name] = {"model": model}
    return f"created agent '{name}' with model '{model}'"

llm = ChatAnthropic(model="claude-sonnet-5")
tools = [check_agent_exists, create_agent_entry]

prompt = ChatPromptTemplate.from_messages([
    ("system", "Always check_agent_exists before create_agent_entry."),
    ("human", "{input}"),
    ("placeholder", "{agent_scratchpad}"),
])

agent = create_tool_calling_agent(llm, tools, prompt)
executor = AgentExecutor(agent=agent, tools=tools, max_iterations=10)

result = executor.invoke({"input": "Register research_agent with claude-sonnet."})
print(result["output"])
```

</Subsection>

<Subsection title="How this maps onto everything already built" variant="b">

- **`@tool`** replaces
  [Lesson 4's `TOOL_REGISTRY`](/02-the-agent-loop/04-writing-the-loop-by-hand/03-handling-multiple-tools/#the-fix-a-dict-mapping-names-to-actual-callables)
  — it builds a schema from the function's type hints and *docstring*
  directly
  ([the same idea, one layer up, from Module 1's Pydantic-to-schema concept](/01-llm-foundations/10-structured-output-and-tool-calling/03-from-a-pydantic-model-to-a-schema/#generating-the-schema-directly-from-a-model-you-already-know)),
  so the docstring here isn't just documentation — it's load-bearing,
  part of what the model actually sees.
- **`"{agent_scratchpad}"`** is LangChain's *own* literal name for the
  accumulating state —
  [Lesson 7's scratchpad](/02-the-agent-loop/07-agent-state-and-the-scratchpad/01-the-scratchpad/),
  confirmed as real, standard terminology, not a name this course
  invented.
- **`create_tool_calling_agent`** builds the decision logic —
  [Lesson 4–5's dispatch and reasoning](/02-the-agent-loop/04-writing-the-loop-by-hand/00-intro/)
  — separately from the loop itself.
- **`AgentExecutor`** *is*
  [Lesson 4's `while` loop](/02-the-agent-loop/04-writing-the-loop-by-hand/02-from-round-trip-to-loop/#the-actual-loop-written-and-running-for-real),
  and `max_iterations=10` *is*
  [Lesson 6's `max_steps`](/02-the-agent-loop/06-termination-failure-and-control/02-max-steps/#the-simplest-possible-guard-a-hard-cap-unconditionally)
  — same guard, now a constructor argument instead of a loop condition
  you wrote.
- **`executor.invoke(...)`** runs the whole loop to completion — the
  same role `run_agent_loop(...)` has played throughout this module.

</Subsection>
