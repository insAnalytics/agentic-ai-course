<Subsection title="Something that's been true since Lesson 4, never named until now" variant="a">

Every loop built since
[Lesson 4](/02-the-agent-loop/04-writing-the-loop-by-hand/02-from-round-trip-to-loop/#the-actual-loop-written-and-running-for-real)
has had a `messages` list, growing with every step — but it's never been
discussed as a concept in its own right. It's worth naming directly now:
this accumulating list is commonly called the agent's **scratchpad** —
the working record of everything that's happened in this specific loop
run.

</Subsection>

<Subsection title="Why it has to exist: the model remembers nothing on its own" variant="b">

Ground this directly in
[Module 1's statelessness](/01-llm-foundations/09-calling-llm-apis-and-processing-responses/03-multi-turn-conversations/#the-api-itself-has-no-memory-between-calls):
the model itself remembers *nothing* between API calls. Every single
piece of context it has about what's happened so far comes entirely from
what's actually included in `messages`, resent in full, every single
time. This means the scratchpad isn't just "conversation history" in some
loose sense — it's the agent's **entire** state, full stop. If something
isn't in `messages`, it doesn't exist as far as the model is concerned,
no matter how recently it actually happened.

</Subsection>

<Subsection title="Watching it grow, concretely" variant="a">

<LiveDemo client:load setupCode={REACT_FAKE_CLIENT} code={`def get_weather(location: str) -> str:
    return f"It's sunny in {location}."

TOOL_REGISTRY = {"get_weather": get_weather}

client = FakeLLMClient(scripted_responses=[
    [ThinkingBlock(thinking="I should check the weather in Paris."), ToolUseBlock(name="get_weather", input={"location": "Paris"})],
    [TextBlock(text="It's sunny in Paris today!")],
])

messages = [{"role": "user", "content": "What's the weather in Paris?"}]
print(f"step 0 -- messages: {len(messages)} entries")

while True:
    response = client.create(messages=messages)
    action_block = None
    for b in response.content:
        if b.type == "thinking":
            print(f"[reasoning]: {b.thinking}")
        else:
            action_block = b

    if action_block.type == "tool_use":
        tool_function = TOOL_REGISTRY[action_block.name]
        result = tool_function(**action_block.input)
        messages.append({"role": "assistant", "content": response.content})
        messages.append({"role": "user", "content": [{"type": "tool_result", "tool_use_id": action_block.id, "content": result}]})
        print(f"after tool call -- messages: {len(messages)} entries")
    elif action_block.type == "text":
        print(f"final answer: {action_block.text}")
        break

print(f"final scratchpad size: {len(messages)} entries")`} />

(The updated fake client is already defined for this demo, and the tool
result carries its call's `id` as `tool_use_id`, as in earlier lessons.)

`messages` starts with exactly one entry — the original question — and
grows to three by the time the loop finishes: the question, the
model's tool-call turn (with its reasoning preserved inline), and the
tool's result. This list *is* everything the agent knows about this
interaction; there's genuinely nowhere else any of it is being kept.

</Subsection>

<Subsection title="What this concept is deliberately not covering" variant="b">

Worth being precise about scope: this is the *within-one-loop-run*
accumulating record — not a more sophisticated memory system that
persists across separate, unrelated sessions, involves retrieval, or
handles compaction once a scratchpad grows very large. That fuller
treatment of memory belongs to a later module entirely, the context and
memory module — this lesson's scratchpad is specifically the record of one
task, from start to finish, nothing more.

</Subsection>
