<Subsection title="Making the packaging concrete, in code this sandbox can actually run" variant="a">

`create_agent` can't run here — no real package, no real network — but
the *packaging* it does is something this module already has every
piece of, and building a small class around it makes
[the four things a framework provides](/02-the-agent-loop/11-from-hand-rolled-to-a-runtime/01-what-a-framework-actually-provides/)
concrete rather than abstract:

<LiveDemo client:load setupCode={REACT_FAKE_CLIENT} code={`class Agent:
    def __init__(self, client, system_prompt: str, tools: list, max_steps: int = 10):
        self.client = client
        self.system_prompt = system_prompt
        self.tools = {tool.__name__: tool for tool in tools}
        self.max_steps = max_steps

    def invoke(self, user_message: str) -> str:
        messages = [
            {"role": "system", "content": self.system_prompt},
            {"role": "user", "content": user_message},
        ]
        for step_count in range(1, self.max_steps + 1):
            response = self.client.create(messages=messages)
            messages.append({"role": "assistant", "content": response.content})

            tool_calls = [block for block in response.content if block.type == "tool_use"]
            if not tool_calls:
                return "".join(block.text for block in response.content if block.type == "text")

            results = []
            for call in tool_calls:
                tool_function = self.tools[call.name]
                output = tool_function(**call.input)
                results.append({"type": "tool_result", "tool_use_id": call.id, "content": str(output)})
            messages.append({"role": "user", "content": results})
        return f"stopped after reaching the maximum of {self.max_steps} steps without a final answer"

def get_weather(location: str) -> str:
    return f"It's sunny in {location}."

client = FakeLLMClient(scripted_responses=[
    [ThinkingBlock(thinking="I should check the weather."), ToolUseBlock(name="get_weather", input={"location": "Paris"})],
    [TextBlock(text="It's sunny in Paris today!")],
])

agent = Agent(client, system_prompt="Always check the weather before answering.", tools=[get_weather], max_steps=5)
print(agent.invoke("What's the weather in Paris?"))`} />

(The fake client's classes are already defined for this demo.) Every
piece this concept named is right here: `system_prompt` set once in
`__init__`, exactly the way a framework's own `system_prompt` parameter
works; `self.tools`, built from `tool.__name__` — every Python function
is itself an object, and `.__name__` is the plain string it carries its
own definition-time name in
([`func.__name__` did the same job inside Module 0's call-forwarding wrapper](/00-python-essentials/03-functions-and-reuse/02-args-and-kwargs/#why-this-matters-for-agent-code-forwarding-calls))
— is a real `TOOL_REGISTRY`, just built automatically from a list
instead of written by hand; `max_steps` caps the loop exactly as it did
in Lesson 6; and `invoke`'s body *is*
[Lesson 5's corrected loop](/02-the-agent-loop/05-react-and-reasoning-in-the-loop/01-the-react-pattern/#the-fix-gather-every-tool-call-act-on-all-of-them-reply-once),
now living inside a method instead of a bare function. A framework's
`create_agent` does more — real networking, real retries, a real
graph engine underneath — but structurally, this *is* what it packages.
