<Subsection title="The same agent, in LangChain" variant="a">

```python
from langchain.agents import create_agent
from langchain.tools import tool

@tool
def check_agent_exists(name: str) -> bool:
    """Check whether an agent with this name already exists in the registry."""
    return name in registry

@tool
def create_agent_entry(name: str, model: str) -> str:
    """Create a new agent entry in the registry."""
    registry[name] = {"model": model}
    return f"created agent '{name}' with model '{model}'"

agent = create_agent(
    model="anthropic:claude-sonnet-5",
    tools=[check_agent_exists, create_agent_entry],
    system_prompt="Always check_agent_exists before create_agent_entry.",
)

result = agent.invoke(
    {"messages": [{"role": "user", "content": "Register research_agent with claude-sonnet."}]},
    config={"recursion_limit": 10},
)
print(result["messages"][-1].content)
```

</Subsection>

<Subsection title="How this maps onto everything already built" variant="b">

- **`@tool`** replaces
  [Lesson 4's `TOOL_REGISTRY`](/02-the-agent-loop/04-writing-the-loop-by-hand/03-handling-multiple-tools/#the-fix-a-dict-mapping-names-to-actual-callables)
  — it builds a schema from the function's type hints and *docstring*
  directly
  ([the same idea, one layer up, from Module 1's Pydantic-to-schema concept](/01-llm-foundations/10-structured-output-and-tool-calling/03-from-a-pydantic-model-to-a-schema/#generating-the-schema-directly-from-a-model-you-already-know)),
  so the docstring here isn't just documentation — it's load-bearing,
  part of what the model actually sees.
- **`system_prompt`** is a direct parameter now, not a message assembled
  by hand — but it plays exactly the role
  [Lesson 3 gave the system prompt](/02-the-agent-loop/03-the-system-prompt-as-agent-design/00-intro/):
  a standing instruction the model sees on every turn, here enforcing
  the same check-before-create discipline this module's own system
  prompts have used throughout.
- **The `{"messages": [...]}` passed to `invoke`** is
  [Lesson 7's scratchpad](/02-the-agent-loop/07-agent-state-and-the-scratchpad/01-the-scratchpad/)
  by another name — a growing list of messages *is* the agent's state,
  whether it's a variable this module built by hand or the input/output
  shape of a framework's own `invoke` call. `result["messages"]` comes
  back holding the *entire* accumulated conversation, tool calls and
  all, for exactly the same reason Lesson 7's `messages` list had to
  hold everything: the model remembers nothing between calls.
- **`create_agent`** builds the decision logic and the loop together —
  [Lesson 4's dispatch](/02-the-agent-loop/04-writing-the-loop-by-hand/02-from-round-trip-to-loop/#the-actual-loop-written-and-running-for-real)
  and
  [Lesson 5's reasoning-before-acting](/02-the-agent-loop/05-react-and-reasoning-in-the-loop/01-the-react-pattern/)
  — and compiles them onto LangGraph, the graph-execution engine
  LangChain's agents now run on.
- **`config={"recursion_limit": 10}`**, passed to `invoke` rather than
  the agent's own constructor, *is*
  [Lesson 6's `max_steps`](/02-the-agent-loop/06-termination-failure-and-control/02-max-steps/#the-simplest-possible-guard-a-hard-cap-unconditionally)
  — the same hard cap on how many steps a single run can take, enforced
  by the underlying graph engine rather than a loop condition you wrote
  yourself. Exceed it and LangGraph raises an error, the framework's
  equivalent of this module's own clean, hand-written stop.

</Subsection>
