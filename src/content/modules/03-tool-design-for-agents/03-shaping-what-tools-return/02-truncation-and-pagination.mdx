<Subsection title="The fix for a result that could be huge: cap it, and say so" variant="a">

[Concept 1 showed the real cost of an unbounded result](/03-tool-design-for-agents/03-shaping-what-tools-return/01-why-a-huge-tool-result-hurts/#a-tool-result-is-just-more-input-tokens)
— the fix isn't complicated, but it has to be done carefully: cap the
result size, and make it *obvious* to the model that truncation happened,
rather than silently dropping data and letting the model reason from an
incomplete picture as if it were complete.

<LiveDemo client:load code={`def list_all_agents(registry: dict, limit: int = 20) -> str:
    entries = list(registry.items())
    shown = entries[:limit]
    lines = [f"{name}: {info}" for name, info in shown]
    result = "\\n".join(lines)
    if len(entries) > limit:
        result += f"\\n\\n... showing {limit} of {len(entries)} total agents. Use offset to see more."
    return result

huge_registry = {f"agent_{i}": {"model": "claude-sonnet"} for i in range(5000)}
print(list_all_agents(huge_registry, limit=3))`} />

The explicit `"showing 3 of 5000"` line is the crucial part — without it,
the model has no way to know this isn't the complete list, and might
confidently answer a question ("how many agents are there?") with a badly
wrong number,
[exactly the kind of confident-but-wrong output Module 1's hallucination coverage warned about](/01-llm-foundations/04-how-llms-generate-text/04-hallucination-as-a-direct-consequence/#not-a-malfunction-the-same-mechanism-landing-on-a-wrong-answer)
— except here the wrongness would come from an incomplete tool result,
not the model's own knowledge gap.

</Subsection>

<Subsection title="Pagination: letting the model ask for more, only if it needs to" variant="b">

<LiveDemo client:load code={`def list_all_agents_paginated(registry: dict, offset: int = 0, limit: int = 20) -> str:
    entries = list(registry.items())
    page = entries[offset:offset + limit]
    lines = [f"{name}: {info}" for name, info in page]
    result = "\\n".join(lines)
    total = len(entries)
    if offset + limit < total:
        result += f"\\n\\n... showing {offset}-{offset + len(page)} of {total}. Call again with offset={offset + limit} for more."
    return result

huge_registry = {f"agent_{i}": {"model": "claude-sonnet"} for i in range(5000)}
print(list_all_agents_paginated(huge_registry, offset=0, limit=3))`} />

`offset` and `limit` — an ordinary parameter pair,
[designed with the same clarity discipline as Lesson 1](/03-tool-design-for-agents/01-designing-tools-a-model-can-use-well/02-parameter-design/#the-schema-constrains-shape-not-whether-the-shape-makes-sense)
— let the model request additional pages only when a task genuinely needs
them, rather than paying the full cost of every result on every call
regardless of actual need.

</Subsection>
