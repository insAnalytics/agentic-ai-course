<WhyItMatters>
  This is where the last three lessons meet.
  [Lesson 5](/03-tool-design-for-agents/05-the-model-context-protocol/00-intro/)
  described the protocol,
  [Lesson 6](/03-tool-design-for-agents/06-building-an-mcp-server/00-intro/)
  built a server, and this lesson connects the registry agent from
  [Module 2's loop](/02-the-agent-loop/05-react-and-reasoning-in-the-loop/00-intro/)
  to servers it didn't write and doesn't control.

  That shift changes what the host is responsible for. When every tool
  lived in your own `TOOL_REGISTRY`, you knew every name, every
  description and every behavior. With MCP, tools arrive from outside:
  names that clash, names the model API won't accept, more tools than any
  task needs. The host's job is to turn all of that into a small, clean,
  well-routed list for the model, and to be the one place that decides
  which of those tools this agent may use at all.
</WhyItMatters>
