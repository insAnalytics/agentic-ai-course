<Subsection title="A tool result is just more input tokens" variant="a">

<LiveDemo client:load code={`def list_all_agents(registry: dict) -> str:
    return "\\n".join(f"{name}: {info}" for name, info in registry.items())

huge_registry = {f"agent_{i}": {"model": "claude-sonnet"} for i in range(5000)}
result = list_all_agents(huge_registry)
print(f"result length: {len(result)} characters, roughly {len(result) // 4} tokens")`} />

A tool's result isn't special — it's
[the exact same input-token accounting from Module 1](/01-llm-foundations/09-calling-llm-apis-and-processing-responses/02-the-response-shape/#usage-tokens-finally-readable-after-the-fact),
consuming
[the same shared context-window budget](/01-llm-foundations/06-context-windows-and-kv-cache/01-what-a-context-window-is/#the-total-token-budget-for-one-request)
and costing
[the same per-token rate](/01-llm-foundations/11-quantization-cost-and-operational-concerns/03-token-based-pricing/#the-basic-pricing-mechanics)
as anything else sent to the model. A single unbounded result here is
nearly 50,000 tokens — a real, expensive, budget-consuming cost, for a
question that very likely only needed a handful of those 5,000 entries.

</Subsection>
