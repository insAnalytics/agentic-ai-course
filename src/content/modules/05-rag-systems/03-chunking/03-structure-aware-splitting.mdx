<Subsection title="Cut where the author already did" variant="a">

Documents come with boundaries built in. A heading starts a new topic. A
blank line ends a paragraph, and a paragraph is usually one idea. A code
block is one unit that means nothing in halves. A **structure-aware**
chunker cuts at those boundaries, and only falls back to cutting blindly
when a single unit is too big for any chunk.

It works in three steps:

1. **Split at headings,** recording where each section sits in the
   document.
2. **Split each section into blocks:** paragraphs, and code blocks kept
   whole.
3. **Pack blocks into chunks** up to a size limit, starting each chunk with
   its section's heading.

This relies on the structure being written down, as it is in this corpus's
Markdown. PDFs, scans and slides don't hand it over, and a table cut between
rows loses the header that gives its cells meaning.
[Lesson 5](/05-rag-systems/05-document-parsing/00-intro/) recovers structure
from documents like those before they reach a chunker.

The helpers for the first two steps, and for the fallback, are loaded for
the rest of this lesson:

```python
def split_blocks(text: str) -> list[str]:
    """Paragraphs and whole code blocks: split at blank lines, except inside a code block."""
    blocks, lines, in_code = [], [], False
    for line in text.splitlines():
        if line.startswith(FENCE):
            in_code = not in_code
        if not line.strip() and not in_code:
            if lines:
                blocks.append("\n".join(lines))
                lines = []
        else:
            lines.append(line)
    if lines:
        blocks.append("\n".join(lines))
    return blocks

def heading_sections(document: dict) -> list[dict]:
    """Split at Markdown headings (not inside code blocks), recording each section's heading path.
    A section with nothing under its heading is dropped: its heading lives on in the paths below it."""
    sections, stack, heading, body, in_code = [], [], "", [], False

    def close():
        text = "\n".join(body).strip()
        if text:
            path = " > ".join([document["title"], *(title for _, title in stack)])
            sections.append({"heading": heading, "path": path, "body": text})

    for line in document["text"].splitlines():
        if line.startswith(FENCE):
            in_code = not in_code
        match = None if in_code else re.match(r"(#{1,6}) (.+)", line)
        if match:
            close()
            level = len(match.group(1))
            # a heading replaces any heading at its level or deeper; level 1 is the document's title
            stack = [(lvl, title) for lvl, title in stack if lvl < level]
            if level > 1:
                stack.append((level, match.group(2).strip()))
            heading, body = line, []
        else:
            body.append(line)
    close()
    return sections

def pack_lines(lines: list[str], max_tokens: int) -> list[str]:
    """Group lines into parts of at most max_tokens; a line longer than that is cut into fixed-size pieces."""
    width = max_tokens * CHARS_PER_TOKEN
    lines = [line[start:start + width] for line in lines for start in range(0, max(len(line), 1), width)]
    parts, current = [], []
    for line in lines:
        if current and count_tokens("\n".join([*current, line])) > max_tokens:
            parts.append("\n".join(current))
            current = []
        current.append(line)
    if current:
        parts.append("\n".join(current))
    return parts
```

<Subsection title="Sections, and where they sit" variant="b">

`heading_sections` records each section's **path**: the document's title
followed by every heading above it. In a long reference page, that path is
often the only place a section's topic is named:

<LiveDemo client:load dataFiles={RAG_EVAL_DATA} setupCode={SETUP} code={PATHS_DEMO} />

A section called "Example" means nothing on its own. Its path says it's an
example of the `<route>` setting in Alertmanager's configuration. The path
goes into every chunk's metadata, and the heading line itself goes at the
top of every chunk's text, so the heading is searchable too. The rest of the
path isn't yet: search reads only the text, and the text says "Example".
[Lesson 9](/05-rag-systems/09-contextual-chunks/01-chunks-that-dont-say-what-theyre-about/)
puts the path where search can see it.

`heading_sections` also drops sections with nothing under their heading,
like the
["## Metrics" parent headings earlier in this lesson](/05-rag-systems/03-chunking/01-why-documents-are-split/#the-corpus-uncut).
Those headings aren't lost: they appear in the paths of the sections below
them.

</Subsection>

<Subsection title="Paragraphs, and whole code blocks" variant="a">

Splitting a section at every blank line would also split code blocks,
because code often contains blank lines. `split_blocks` tracks whether it's
inside a code block and only splits outside one:

The command-line help example contains blank lines of its own. Split
naively, it would become three pieces, and a chunk boundary could fall
between them.

<Subsection title="Packing blocks into chunks" variant="b">

With the blocks in hand, packing is greedy: add blocks to the current
chunk, in order, until the next one would take it over the limit, then
start a new chunk. Two details matter:

- **The heading counts.** Each chunk's text starts with its section's
  heading line, and the limit applies to the whole chunk, heading
  included. So the room for blocks is the limit minus the heading.
- **A block too big for any chunk has to be cut.** `pack_lines` splits it
  at line breaks, which keeps lines of code and sentences on separate lines
  intact, and cuts a single overlong line only as a last resort. A code
  block longer than a whole chunk still ends up in pieces; no chunker can
  avoid that, but cutting between lines is the least damaging place.

</Subsection>

<Subsection title="What every chunk carries" variant="a">

Each chunk carries its document's metadata, plus where it sits:

- **`doc_id` and `title`:** the source, for citing it in an answer, which
  Lesson 10 builds on.
- **`section`:** the heading path, which locates the chunk within the
  document and names its topic.
- **`chunk`:** its position among the document's chunks, which makes each
  chunk's identity unique and lets its neighbours be found, which Lesson 9
  uses.
- **`date`:** for telling a current source from a stale one, like the
  monitoring guide's out-of-date rate limit.
- **`access`:** which groups may read it. Lesson 13 filters on it at
  retrieval time, so it has to be on every chunk from the moment the chunk
  is made.
- **`source_type`:** official, wiki or vendor, for weighing how far to
  trust a chunk.

All of it is decided here, at indexing time. Anything a chunk doesn't carry
now can't be filtered on, cited or checked later.

</Subsection>
